How I think

Processes before tools

I build the workflow first, then find the right tool for it. Most of these projects started as a problem I kept running into — not as an excuse to try something new.

Iterate in public

None of these were built in one session. The plan-my-week skill has been corrected, extended, and debugged across a dozen conversations. That's the real work.

AI as infrastructure

I'm interested in AI as operational infrastructure — not a chatbot to ask questions, but a system you configure to do consistent, repeatable work on your behalf.

Content is structure

Two of these projects (the inbox system and the TEFL reference library) are built entirely from documents — no code. Good knowledge architecture is as valuable as good code architecture.

Small problems are real problems

A grocery price comparison and a lunchbox planner aren't glamorous. But building them fast and well, with the right tradeoffs, is exactly what good product thinking looks like at scale.

Learning by doing

I'm also studying TEFL — and built my study system in the same environment I use for everything else. Learning about a domain and building tools for that domain are the same activity for me.
